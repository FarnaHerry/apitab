# 当前 UI 布局与待核验问题

本文对照当前应用源码记录布局，不把源码中的 `Island` 命名理解为仍在使用岛屿风格。
尺寸均为 HuxerUI 逻辑尺寸（dp），不是物理像素；`Frame` 的目标尺寸与最小尺寸仍服从父约束。

## 外壳与表面

主窗口入口在 `src/app.cpp`，布局在 `src/ui/app.cpp`，拆出的项目窗口使用
`ChildWindowRoot`。主/子窗口初始尺寸都是 1180×760，最小尺寸都是 800×600。

```text
MinimalThemed
└─ 根 Column（CrossAlign Stretch）
   ├─ WindowTitleBar：Logo / 主页 / 项目与设置标签 / 操作区 / 系统窗口按钮
   ├─ 主 Row（Grow + CrossAlign Stretch）
   │  ├─ SideShell：仅项目工作区显示
   │  └─ IndexedPages：主页 / 各项目工作区 / 已打开的全局设置
   │     └─ 每个顶级页面各自包一层 PageCard：外边距、外轮廓与裁剪
   └─ 0.5dp 通栏线 + 22dp 状态栏：仅项目工作区显示
```

子窗口直接显示单个项目的 `PageCard`，不再套顶级 `IndexedPages`。项目工作区内部的
请求、压测、历史、项目设置由另一层 `IndexedPages` 切换。切换只改变选中页面；关闭
标签、改变 Key 或条件分支移除节点才会卸载相应子树，不能据此声称所有请求编辑器也始终保活。

三层表面应分别描述：

| 层级 | 当前契约 |
|---|---|
| 窗口画布 | 深色为 `#000000`；标题栏、项目侧栏直接使用画布 |
| PageCard | 外边距 8dp，小圆角、裁剪和 1dp 外框；底色深色 `#303030`、浅色 `#f6f8fa` |
| 页面工作面 | `islands.base`：深色 `#121212`、浅色 `#ffffff`；普通分区无边框、直角，相邻区域只画一条 0.5dp 线 |

页面工作面会覆盖其下方的卡片底色；卡片底色不等于所有内部分区的底色。普通
`IslandSurface` 的 Base/Raised/Active 都使用同一工作面，列表行 hover/选中才单独使用
`islands.raised/active`。浮层与危险面保留自己的底色和边界。

标题栏期望高度为 24dp，不是所有子项及最终标题栏都强制为 24dp：主窗口头像为 28dp，
系统窗口按钮也可能提高高度下限。根 Column 不设置分区间距，页面外边距由 PageCard 提供。

## 页面分区与滚动

| 页面 | 常规分区 | 滚动所有者 |
|---|---|---|
| 主页 | 左组织栏 240dp，右项目区 Grow，中间单线 | 组织 VirtualList；项目 VirtualGrid，自适应列数，卡片 200×96dp |
| 请求 | 左请求树，右编辑/响应区，分区由拖条分隔 | 树、编辑内容和响应各自滚动；固定工具栏不随内容滚动 |
| 压测 | 左用例树 250dp，右配置/脚本/汇总/输出 | 左树滚动；右侧整体 ScrollView，其中输出另有 260dp 高的 VirtualList |
| 历史 | 左分类栏 168dp，右记录区 | 记录 VirtualList；请求历史分页栏固定在面板底部 |
| 全局设置 | 左分类栏，右设置内容 | 左栏固定，右侧 ScrollView；分类栏宽按 192dp 基准扣除外侧缩进 |
| 项目设置 | 元信息、公共请求头、保存按钮单列排列 | 公共请求头表 VirtualList，不再外套整页 ScrollView |

HTTP 调试页右侧按以下层级布局：

```text
右侧 Column
├─ 编辑区（Grow；期望最小 480×300dp）
│  ├─ 请求标签条：横向滚动标签 + 环境组合控件
│  └─ RequestEditor
│     ├─ 调试 / 文档 / 测试用例 / Mock + 请求名称
│     ├─ 方法 / URL / 发送 / 保存 / 更多
│     ├─ Auth / Params / Headers / Cookies / Body / 设置
│     └─ 当前分区：固定头 + 独立滚动内容
├─ 横向 ResizeHandle
└─ 响应区：Body / Headers / Cookies / 可选 Preview
```

请求树宽度 State 默认 260dp，拖动范围 180～420dp；响应高度 State 默认 260dp，范围
140～640dp。这些是请求值，实际分配还受父约束影响。拖条独占 6dp 命中热区，中央只画
0.5dp 线，悬停/拖动只改变线色，不叠在面板边缘，也不附加第二条分隔线。

文档、测试用例和 Mock 隐藏响应区；WS/TCP 使用整个右侧会话区，顶部操作固定、事件流
独立滚动；gRPC 是占位。新建请求的 Flow 按实际可用宽度换行，没有固定两列契约。

KV 表与代码编辑器拥有自己的滚动，调用方不再追加同轴 ScrollView。响应 Body 完成态
使用只读编辑器，传输中使用流式 ScrollView；Headers/Cookies 使用 VirtualList。

## 已确认的约束问题与后续验证

以下记录实现事实及其影响；本次仅整理描述，未修改布局行为，也未做运行时溢出验证。

1. **桌面窄窗与 Compact 策略脱节。** 默认视口断点为 600/840dp，主/子窗口最小宽
   800dp，正常桌面缩窗不会进入 Compact。已有的上下堆叠、顶部分类选择器和侧栏缩窄
   不能描述成已覆盖桌面最小窗口。后续应按实际内容可用空间验证断点，而非只降低最小窗口尺寸。
2. **请求页分区预算超过最小窗口。** 仅按侧栏 64 + 卡片两侧留白 16 + 默认请求树
   260 + 拖条 6 + HTTP 编辑区期望最小宽 480，相加已是 826dp。垂直方向即使按标题栏
   24 + 状态栏及分隔线 22.5 + 卡片留白 16 + 编辑区 300 + 拖条 6 + 默认响应区 260，
   也达到 628.5dp。父约束可以压缩目标尺寸，但这些数值不能证明最小窗口下内容完整可见。
   拖动目前只按固定范围限幅，未结合窗口剩余尺寸保护相邻区域；应验证缩窗及拖到两端的行为。
3. **主页 Compact 分支的尺寸声明冲突待核验。** 组织栏原有宽 240dp、最小高 240dp，分支只追加
   最大高 220dp，未显式解除原宽度与高度下限。应先验证 Frame 合并和父约束后的结果，
   再描述为满宽顶部组织栏。
4. **压测页响应式策略不完整。** 根布局始终左右排列，左栏固定 250dp；Compact 主要调整
   右侧内边距，参数 Flow 根据宽度换行。右侧整体滚动与输出区滚动形成有意嵌套，应验证
   窄窗下表单可用宽度和输出区滚轮在边缘的交接。

维护入口：外壳 `src/ui/app.cpp`；尺寸及分派 `request_page.cpp`；编辑器
`request_editor.cpp`；请求标签 `request_tab_strip.cpp`；表面令牌 `common.cpp` / `ui.h`。
后续改变尺寸、断点或滚动所有权时，同步更新本说明；历史计划不作为当前实现证明。
